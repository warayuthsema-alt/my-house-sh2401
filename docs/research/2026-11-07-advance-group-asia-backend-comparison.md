# เปรียบเทียบเซิร์ฟเวอร์และบริการหลังบ้าน (Backend) สำหรับระบบประวัติลูกค้า
## บริษัทแอดวานซ์กรุ๊ปเอเซีย (ธุรกิจกำจัดแมลง · 43 สาขา)

จัดทำ: 7 พ.ย. 2026 · อัตราแลกเปลี่ยนที่ใช้: **1 USD ≈ 33.7 บาท** (ต้นเดือน พ.ย. 2026)

> ราคาทั้งหมดเป็น **ราคาประมาณการ** ส่วนใหญ่มาจากเว็บไซต์เปรียบเทียบและบล็อก ไม่ใช่ใบเสนอราคาจริง ก่อนตั้งงบประมาณควรตรวจราคากับหน้าราคาของผู้ให้บริการอีกครั้ง หรือขอใบเสนอราคา

## 1. โจทย์ของระบบ

| หัวข้อ | รายละเอียด |
|---|---|
| ใช้ทำอะไร | เก็บข้อมูลลูกค้าและประวัติทั้งหมด แบบเดียวกับที่โรงพยาบาลเก็บแฟ้มประวัติคนไข้ ดูย้อนหลังออนไลน์ได้ |
| ใครใช้ | พนักงานออฟฟิศประมาณ **200 คน** จาก 43 สาขา (ไม่รวมช่างหน้างาน) |
| ระบบเดิม | Excel |
| ข้อมูลที่มี | ยังไม่มีตัวเลขจำนวนลูกค้า |

**ข้อสมมติที่ใช้คำนวณราคา** (ปรับได้เมื่อมีตัวเลขจริง)

| ขนาด | จำนวนลูกค้า | ฐานข้อมูล | ไฟล์แนบ (สัญญา/รูป/PDF) | คนใช้พร้อมกัน |
|---|---|---|---|---|
| เล็ก | ไม่เกิน 20,000 ราย | ไม่เกิน 5 GB | ไม่เกิน 50 GB | 30–50 คน |
| กลาง | 20,000–100,000 ราย | 5–20 GB | 50–300 GB | 50–100 คน |
| ใหญ่ | มากกว่า 100,000 ราย | 20–100 GB | 300 GB–1 TB | 100–200 คน |

200 คน และหลักแสนรายการ ถือเป็น **งานขนาดเล็กถึงกลาง** สำหรับเซิร์ฟเวอร์สมัยนี้ ตัวที่ทำให้ราคาต่างกันจริงๆ คือ **ไฟล์แนบ** **ระบบสำรองข้อมูล** และ **ค่าลิขสิทธิ์รายคน**

### ทำไมข้อมูลแบบ "แฟ้มประวัติ" ถึงเหมาะกับฐานข้อมูลแบบ SQL

ข้อมูลของบริษัทมีความสัมพันธ์กันเป็นชั้นๆ:

```
สาขา ─┬─ ลูกค้า ─┬─ สถานที่บริการ (บ้าน/โรงงาน/ร้านอาหาร)
      │          ├─ สัญญา ── รอบบริการ
      │          ├─ ประวัติการเข้าบริการ (วันที่ · ปัญหา · สารเคมีที่ใช้ · ผล)
      │          ├─ เรื่องร้องเรียน / การติดตาม
      │          └─ ไฟล์แนบ
      └─ พนักงาน (สิทธิ์ดูเฉพาะลูกค้าของสาขาตัวเอง)
```

ฐานข้อมูล SQL (เช่น PostgreSQL) เก็บข้อมูลที่โยงกันแบบนี้ได้ดี ค้นหาและออกรายงานข้ามสาขาได้ง่าย (เช่น "ลูกค้าที่สัญญาจะหมดเดือนหน้า แยกตามสาขา") ส่วนฐานข้อมูลแบบ NoSQL (เช่น Firestore) ทำรายงานลักษณะนี้ได้ยากกว่า

## 2. สรุปสั้น (อ่านส่วนนี้ส่วนเดียวก็พอ)

| อันดับ | ทางเลือก | ค่าใช้จ่ายโดยประมาณ / เดือน | เหมาะเมื่อ |
|---|---|---|---|
| ⭐ 1 | **Supabase Pro** (เซิร์ฟเวอร์สิงคโปร์) | **~1,000–6,000 บาท** | ต้องการราคาถูก เริ่มเร็ว ใช้ PostgreSQL มีระบบล็อกอินและเก็บไฟล์ให้ในตัว |
| 2 | **NIPA Cloud** หรือ **AWS ภูมิภาคประเทศไทย** | ~5,000–15,000 บาท + ค่าทีมดูแล | บริษัทกำหนดว่าข้อมูลลูกค้าต้องเก็บในประเทศไทย |
| 3 | **AppSheet** (ถ้าบริษัทใช้ Google Workspace อยู่แล้ว) | 0–67,000 บาท | อยากได้ระบบเร็วโดยไม่ต้องเขียนโปรแกรม และอยู่ต่อจาก Excel/Google Sheets |
| ✗ | Firebase | ~0–1,500 บาท | ถูก แต่ไม่เหมาะกับข้อมูลแบบแฟ้มประวัติและรายงานข้ามสาขา |
| ✗ | Power Apps | ~135,000 บาท | แพงเกินไปสำหรับ 200 คน (คิดเงินรายคน) |

**คำแนะนำ:** ใช้ **Supabase Pro** เป็นตัวหลัก เพราะคุ้มที่สุดสำหรับ 200 คน ได้ทั้งฐานข้อมูล ระบบล็อกอิน การกำหนดสิทธิ์ตามสาขา (Row Level Security) และที่เก็บไฟล์ 100 GB ในราคาเริ่มต้นประมาณ 1,000 บาทต่อเดือน และย้ายออกได้ไม่ติดค่าย เพราะเป็น PostgreSQL มาตรฐาน
ถ้าฝ่ายกฎหมายกำหนดว่าข้อมูลต้องอยู่ในประเทศไทย ให้เลือก NIPA Cloud หรือ AWS ภูมิภาคประเทศไทยแทน

## 3. รายละเอียดแต่ละทางเลือก

### 3.1 Supabase ⭐ (แนะนำ)

ฐานข้อมูล PostgreSQL พร้อมระบบล็อกอิน ที่เก็บไฟล์ และ API ในตัว มีเซิร์ฟเวอร์ที่ **สิงคโปร์** (ใกล้ไทย เปิดได้เร็ว)

| รายการ | ราคา |
|---|---|
| Pro plan | $25/เดือน (รวมเครดิตค่าเครื่อง $10) |
| ฐานข้อมูลที่รวมอยู่ | 8 GB (เกินคิด $0.125/GB) |
| ที่เก็บไฟล์ที่รวมอยู่ | 100 GB (เกินคิดประมาณ $0.021/GB) |
| รับส่งข้อมูลที่รวมอยู่ | 250 GB/เดือน (เกินคิด $0.09/GB) |
| สำรองข้อมูลรายวัน | รวมอยู่ใน Pro (เก็บ 7 วัน) |
| กู้ข้อมูลย้อนเวลา (PITR) | +$100/เดือน ต่อการเก็บย้อนหลัง 7 วัน |
| Team plan (มี SSO สำหรับหน้าผู้ดูแล, SOC2) | $599/เดือน |

**ประมาณการของบริษัท**

| ขนาด | ส่วนประกอบ | USD/เดือน | บาท/เดือน |
|---|---|---|---|
| เล็ก | Pro + เครื่อง Small | ~$30 | **~1,000** |
| กลาง | Pro + เครื่อง Medium + ไฟล์ 300 GB | ~$80–115 | **~2,700–3,900** |
| กลาง + กู้ข้อมูลย้อนเวลา | ข้างบน + PITR 7 วัน | ~$180–215 | **~6,000–7,200** |
| ต้องการ SSO/SOC2 | Team plan + เครื่อง Medium | ~$650 | ~22,000 |

**ข้อดี**
- ราคาคงที่ คาดเดาได้ ไม่คิดเงินรายคน (200 หรือ 2,000 คนราคาเท่ากัน)
- กำหนดสิทธิ์ "พนักงานเห็นเฉพาะลูกค้าสาขาตัวเอง" ได้ที่ระดับฐานข้อมูล
- เป็น PostgreSQL มาตรฐาน ย้ายไปเซิร์ฟเวอร์อื่น (รวมถึงเซิร์ฟเวอร์ในไทย) ได้ภายหลัง
- เปิดโค้ด (open source) ติดตั้งบนเซิร์ฟเวอร์ของบริษัทเองได้ถ้าจำเป็น
- repo นี้ใช้ Supabase อยู่แล้ว (`supabase/house.sql`) มีประสบการณ์ในทีม

**ข้อควรระวัง**
- เซิร์ฟเวอร์อยู่สิงคโปร์ ไม่ใช่ไทย (ดูหัวข้อ PDPA)
- ต้องเขียนหน้าเว็บเอง (Supabase เป็นแค่หลังบ้าน)
- จ่ายเป็นดอลลาร์ผ่านบัตรเครดิต ไม่มีใบกำกับภาษีไทย

### 3.2 Firebase (Google)

ฐานข้อมูล NoSQL (Firestore) พร้อมระบบล็อกอินและเก็บไฟล์

| รายการ | ราคา (Blaze plan, ประมาณ) |
|---|---|
| ฟรีต่อวัน | อ่าน 50,000 · เขียน 20,000 · เก็บ 1 GB |
| อ่านเกิน | ~$0.03–0.06 ต่อ 100,000 ครั้ง |
| เขียนเกิน | ~$0.09–0.18 ต่อ 100,000 ครั้ง |
| เก็บข้อมูล | ~$0.15–0.26/GB/เดือน |
| Cloud Storage | ตั้งแต่ 3 ก.พ. 2026 ต้องผูกบัตร (Blaze) |

**ประมาณการ:** 200 คน × อ่านวันละ 300 ครั้ง = 60,000 ครั้ง/วัน → **~0–1,500 บาท/เดือน**

**ทำไมไม่แนะนำ**
- ข้อมูลแฟ้มประวัติที่โยงกันหลายชั้น และรายงานข้ามสาขา ทำได้ยากในฐานข้อมูล NoSQL
- **ไม่มีเพดานค่าใช้จ่าย** ถ้าโปรแกรมเขียนผิดจนอ่านข้อมูลวนซ้ำ บิลจะพุ่งได้ทันที (มีแค่อีเมลเตือน)
- ย้ายออกจาก Google ยาก

### 3.4 คลาวด์ที่มีเซิร์ฟเวอร์ในประเทศไทย

เลือกกลุ่มนี้เมื่อบริษัทต้องการให้ **ข้อมูลอยู่ในประเทศไทย** หรือลูกค้าองค์กรบางรายกำหนดไว้

| บริการ | ราคาโดยประมาณ | ข้อดี | ข้อควรระวัง |
|---|---|---|---|
| **AWS ภูมิภาคประเทศไทย** (ap-southeast-7, 3 ศูนย์ข้อมูล) | ฐานข้อมูล RDS PostgreSQL ขนาด db.r7g.large ~$94–178/เดือน (ขึ้นกับสัญญา 1–3 ปี) + เครื่องเว็บ → รวม **~5,000–15,000 บาท** | มาตรฐานระดับโลก ข้อมูลอยู่ในไทย | ตั้งค่าซับซ้อน ต้องมีคนดูแล AWS |
| **NIPA Cloud** (บริษัทไทย) | ไม่พบราคาเครื่องที่เปิดเผย ต้องใช้เครื่องคำนวณราคาบนเว็บหรือขอใบเสนอราคา (sales@nipa.cloud) | คิดเป็นเงินบาท มีใบกำกับภาษี รับส่งข้อมูลในประเทศไม่คิดเงิน ซัพพอร์ตภาษาไทย | ต้องติดตั้งฐานข้อมูลและระบบเองมากกว่า Supabase |
| **ผู้ให้บริการไทยอื่นๆ** (INET, True IDC, CAT/NT) | ต้องขอใบเสนอราคา | ข้อมูลในไทย ใบกำกับภาษีไทย | ยังไม่ได้ค้นราคาในรอบนี้ |

## 4. ข้อมูลส่วนบุคคล (PDPA) และที่ตั้งเซิร์ฟเวอร์

- ข้อมูลลูกค้า (ชื่อ ที่อยู่ เบอร์โทร) เป็นข้อมูลส่วนบุคคลตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล
- **ส่งข้อมูลไปเก็บต่างประเทศ (เช่น สิงคโปร์) ได้** ถ้ามีมาตรการคุ้มครองที่เหมาะสม เช่น สัญญาประมวลผลข้อมูล (DPA) กับผู้ให้บริการ ซึ่ง Supabase, Google และ AWS มีให้
- สิ่งที่ระบบควรมีไม่ว่าจะเลือกที่ไหน: สิทธิ์ตามสาขา บันทึกว่าใครเปิดหรือแก้ข้อมูลเมื่อไร เข้ารหัสข้อมูล และสำรองข้อมูล
- **ควรให้ฝ่ายกฎหมายหรือ DPO ของบริษัทยืนยัน** ว่ายอมรับการเก็บข้อมูลที่สิงคโปร์ได้หรือไม่ คำตอบนี้คือตัวตัดสินระหว่างทางเลือกที่ 1 กับ 2

## 5. ค่าใช้จ่ายที่ไม่ใช่ค่าเซิร์ฟเวอร์ (มักลืม)

ค่าเซิร์ฟเวอร์เป็นส่วนเล็กของค่าใช้จ่ายทั้งหมด สิ่งที่แพงกว่าคือ:

1. **ค่าพัฒนาระบบ** (หน้าเว็บ ฟอร์ม รายงาน) ถ้าจ้างทำ หรือเวลาของทีม IT
2. **ค่าย้ายข้อมูลจาก Excel** ทำความสะอาดข้อมูล รวมรายชื่อซ้ำ ข้ามสาขา
3. **ค่าดูแลรายเดือน** อัปเดตความปลอดภัย แก้ปัญหา (ทางเลือกแบบติดตั้งเองจะสูงที่สุดในข้อนี้)
4. **ชื่อโดเมนและอีเมล** (ถ้ายังไม่มี) ~500–1,000 บาท/ปี
5. **ค่าโฮสต์หน้าเว็บ** ถ้าใช้ Supabase ร่วมกับ Vercel, Netlify หรือ Cloudflare Pages มักเริ่มต้นฟรี

## 6. สิ่งที่ต้องหาข้อมูลเพิ่มเพื่อให้ราคาแม่นขึ้น

1. จำนวนลูกค้าในไฟล์ Excel ทุกสาขารวมกัน
2. ต้องแนบไฟล์ในแฟ้มลูกค้าหรือไม่ (สัญญาสแกน รูป ใบเสร็จ) และประมาณกี่ไฟล์ต่อราย
3. ฝ่ายกฎหมายยอมให้เก็บข้อมูลนอกประเทศไทยหรือไม่
4. บริษัทใช้ Google Workspace หรือ Microsoft 365 อยู่หรือไม่ และเป็นแพ็กเกจอะไร
5. ต้องการกู้ข้อมูลย้อนหลังได้นานแค่ไหน (1 วัน, 7 วัน, 30 วัน)
6. มีทีม IT ในบริษัทที่จะดูแลระบบหรือไม่ หรือจะจ้างภายนอก
